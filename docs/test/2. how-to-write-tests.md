# 🧑‍💻 Hướng Dẫn Viết Test Chuyên Nghiệp (Testing Best Practices)

Tài liệu này đóng vai trò là kim chỉ nam (Guidelines) giúp bạn tự xây dựng và mở rộng hệ thống Test cho nền tảng ChatHub. Nền tảng sử dụng **Jest (Backend)** và **Vitest (Frontend)**. Do hai công cụ này có bộ API gần như giống nhau (`describe`, `it`, `expect`, `vi`/`jest.fn`), quy chuẩn dưới đây áp dụng được cho cả hai.

## 1. Cấu trúc Thư mục Test (Folder Structure)

Chúng tôi thiết kế theo mô hình **Định vị Cục bộ (Colocation)** kết hợp **Thư mục Mũi nhọn (`__tests__`)**.

```text
src/
├── controllers/
├── models/
├── store/
│   ├── useCallStore.js
│   └── __tests__/                 <-- Đặt thư mục __tests__ song song với file gốc
│       └── useCallStore.test.js   <-- Tên file test giữ nguyên hậu tố .test.js
│
├── utils/
│   ├── formatDate.js
│   └── __tests__/
│       └── formatDate.test.js
```
*Lợi ích:* Tránh việc phải chui vào một thư mục `tests/` khổng lồ ở tít ngoài gốc dự án. Code gốc ở đâu, Test viết ngay cạnh đó.

---

## 2. Mô hình A-A-A (Arrange - Act - Assert)

Mọi file `*.test.js` chuyên nghiệp của Google hay Facebook đều tuân thủ chặt chẽ pattern **3 chữ A**. Bạn tuyệt đối không nên viết Test lộn xộn, mà phải tách bạch 3 bước này bằng dòng trống (blank lines).

```javascript
// Ví dụ: Kiểm thử hàm login
it('should login an existing user', async () => {
    // 1. ARRANGE (Chuẩn bị dữ liệu / Môi trường)
    // Setup: Tạo sẵn user trong DB
    await request(app).post('/api/auth/signup').send({
      email: 'test@example.com',
      password: 'password123',
    });
    const loginPayload = { email: 'test@example.com', password: 'password123' };

    // 2. ACT (Thực thi hành động)
    // Send request tới API Login
    const res = await request(app).post('/api/auth/login').send(loginPayload);

    // 3. ASSERT (Kiểm định kết quả mong đợi)
    // So sánh Status HTTP và Cookie
    expect(res.status).toBe(200);
    expect(res.body.email).toBe('test@example.com');
    expect(res.headers['set-cookie']).toBeDefined(); // Đảm bảo JWT được cấp
});
```

## 3. Quản Lý Vòng Đời Test (Lifecycle Hooks)

Không bao giờ để dữ liệu Test này làm "bẩn" Test khác (Test Pollution). Phải dọn dẹp biến, Mock Data và DB sau mỗi hàm `it()`.

Sử dụng bộ kẹp: `beforeAll`, `beforeEach`, `afterEach`, `afterAll`.

```javascript
import { describe, beforeEach, afterEach, vi } from 'vitest';

describe('useCallStore UI Logic', () => {
  beforeEach(() => {
    // Chạy TRƯỚC mỗi hàm it()
    useCallStore.setState({ callStatus: 'idle' }); // Reset state Zustand
    vi.clearAllMocks(); // Xóa bộ nhớ của các hàm ảo (Mocks function like toast)
  });

  afterEach(() => {
    // Chạy SAU mỗi hàm it() (Dọn dẹp rác cứng nếu cần thiết)
  });

  it('test 1', () => { ... });
  it('test 2', () => { ... });
});
```

## 4. Xử lý Mocking (Thay thế sự thật)

Khi chạy Unit Test, bạn KHÔNG ĐƯỢC PHÉP gọi xuống Database thật, hoặc gửi API ra Internet, hoặc gọi React Element UI thực tế nếu không cần thiết. Quá trình đó gọi là Mocking (Làm giả).

### Giả lập Hàm (Function Mock)
```javascript
// Backend (Jest)
const sendEmailMock = jest.fn().mockResolvedValue(true); // Hàm ảo luôn trả về true

// Frontend (Vitest)
const myMock = vi.fn().mockReturnValue(123);
```

### Giả lập Thư viện bên thứ 3 (Module Mock)
Trong file `useCallStore.test.js`, thay vì để `react-hot-toast` in ra màn hình trình duyệt (nơi Test không hề tồn tại trình duyệt), ta thay máu nó ngay từ dòng 1:

```javascript
// "Bắt cóc" thư viện react-hot-toast, ép nó trả về hàm ảo vi.fn()
vi.mock('react-hot-toast', () => {
  const toastMock = {
    error: vi.fn(),
    success: vi.fn(),
  };
  return {
    default: toastMock,
    toast: toastMock,
  };
});
```
*Hệ quả:* Khi Source Code thật chạy hàm `toast.error('Lỗi!')`, Vitest không in ra trình duyệt, mà nó âm thầm tăng biến đếm của `vi.fn()`. Từ đó ta có thể check: `expect(toast.error).toHaveBeenCalledWith('Lỗi!')`.

## 5. Quy chuẩn Viết Tên (Naming Convention)

Khối `describe` (Nhóm Test) phải đặt tên theo **Tên module / Component đang test**. Tên khối `it` (Cá thể Test) phải đặt theo cú pháp **hành vi mong muốn "should..."** bằng tiếng Anh gốc.

❌ Xấu:
```javascript
describe('Test cai authentication', () => {
  it('test thu sai mat khau', () => { ... })
});
```

✅ Chuẩn Google:
```javascript
describe('Authentication API Controller', () => {
  it('should return 400 when logging in with incorrect password', () => { ... })
  it('should successfully generate JWT cookie on valid signup', () => { ... })
});
```

## Tổng Kết
Bạn hãy coi test runner (Vitest/Jest) như **"Khách hàng khó tính"**. Khách đến cửa hàng (`beforeAll`), yêu cầu dọn sạch bàn (`beforeEach`), gọi món bằng AAA style (`Act`), đòi nếm thử xem đúng vị không (`Assert`), và cuối cùng đứng dậy thu dọn đồ ra về (`afterAll`). Đi theo đúng mô hình này, hệ thống của bạn sẽ vẹn toàn tuyệt đối.
